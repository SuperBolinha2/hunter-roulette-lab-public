## Português

Código do servidor local, testes e descobertas sobre Hunter Roulette. **Não inclui o jogo nem um instalador pronto para jogar.** Git guarda o histórico das mudanças; GitHub guarda a cópia compartilhada na internet.

### Começo: instalar e baixar

1. Peça um convite ao SuperBolinha2 e aceite no GitHub: este projeto é privado.
2. No Windows, instale [GitHub Desktop](https://desktop.github.com/) e entre na sua conta. Não precisa instalar Git separadamente para este tutorial.
3. Instale [Python 3.14](https://www.python.org/downloads/windows/), marcando **Add Python to PATH**, se aparecer. Reabra o terminal após instalar. Use um editor como [VS Code](https://code.visualstudio.com/). Os testes não precisam de Unity, banco de dados ou bibliotecas Python extras.
4. No Desktop: **File → Clone repository → URL**. Cole `https://github.com/SuperBolinha2/hunter-roulette-lab.git`, escolha uma pasta nova fora da instalação original do jogo e clique em **Clone**.

### Meio: testar e modificar

Abra a pasta baixada no Explorador, digite `powershell` na barra de endereço e pressione Enter. Execute os comandos de **Teste local**, abaixo. Se falhar, envie o erro ao grupo.

Antes de editar, avise o que vai fazer. No Desktop, selecione **Current Branch → main**, depois **Fetch origin** e **Pull origin**, se aparecer. Crie sua linha separada de trabalho em **Current Branch → New Branch**, a partir de `main`, por exemplo `work/seu-nome-correcao`. Edite os arquivos e rode os testes novamente.

### Fim: enviar e receber atualizações

Em **Changes**, confira os arquivos, escreva um resumo e clique em **Commit to…**: registra a mudança só no seu computador. **Publish branch** (primeira vez) ou **Push origin** envia ao GitHub. Em **Create Pull Request**, peça revisão e integração na `main`; explique o que mudou e como testou. Aguarde a revisão e os testes automáticos.

Depois da integração, todos voltam à `main` e usam **Fetch origin → Pull origin**. Para outra tarefa, crie outra branch. **Salvar não envia automaticamente; enviar não atualiza automaticamente os outros.** Não publique direto na `main`. Antes de trocar de branch, registre seu trabalho com um commit. Se houver conflito, pare e peça ajuda: não descarte arquivos nem force o envio.

Para jogar, é necessária uma cópia legítima, compatível e preparada para o laboratório. **O cliente Steam sem modificações não está garantido.** Combine a preparação com o responsável; baixar este repositório não instala as alterações do cliente. Veja **Teste no jogo**, abaixo. Nunca envie saves, logs pessoais, senhas, tokens ou arquivos proprietários do jogo.

## Русский

Код локального сервера, тесты и исследования Hunter Roulette. **Игры и готового установщика здесь нет.** Git хранит историю изменений, GitHub — общую копию в интернете.

### Начало: установка и скачивание

1. Попросите приглашение у SuperBolinha2 и примите его на GitHub: проект закрытый.
2. На Windows установите [GitHub Desktop](https://desktop.github.com/) и войдите в аккаунт. Для этого руководства отдельно устанавливать Git не нужно.
3. Установите [Python 3.14](https://www.python.org/downloads/windows/), включив **Add Python to PATH**, если этот пункт есть. Заново откройте терминал. Подойдёт редактор [VS Code](https://code.visualstudio.com/). Для тестов не нужны Unity, база данных или дополнительные пакеты Python.
4. В Desktop: **File → Clone repository → URL**. Вставьте `https://github.com/SuperBolinha2/hunter-roulette-lab.git`, выберите новую папку вне оригинальной установки игры и нажмите **Clone**.

### Работа: тесты и изменения

Откройте скачанную папку в Проводнике, введите `powershell` в адресной строке и нажмите Enter. Выполните команды из раздела **Teste local** ниже. При ошибке отправьте её текст команде.

Напишите команде, над чем будете работать. Выберите **Current Branch → main**, затем **Fetch origin** и **Pull origin**, если кнопка появилась. Через **Current Branch → New Branch** создайте свою ветку от `main`, например `work/your-name-fix`: отдельную линию работы. Измените файлы и повторите тесты.

### Завершение: отправка и обновление

В **Changes** проверьте файлы, напишите краткое описание и нажмите **Commit to…**: пока это запись только на вашем компьютере. **Publish branch** при первой отправке или **Push origin** отправляет изменения на GitHub. Через **Create Pull Request** запросите проверку и добавление в `main`; опишите изменения и тесты. Дождитесь проверки командой и автоматических тестов.

После объединения все выбирают `main` и нажимают **Fetch origin → Pull origin**. Для следующей задачи создайте новую ветку. **Сохранение не отправляет файлы автоматически; отправка не обновляет чужие компьютеры.** Не отправляйте изменения прямо в `main`. Перед сменой ветки сделайте commit. При конфликте попросите помощи: не удаляйте файлы и не используйте принудительную отправку.

Для игры нужна законно полученная совместимая копия клиента, подготовленная для лаборатории. **Работа обычного клиента Steam не гарантируется.** Уточните подготовку у руководителя: скачивание кода не устанавливает изменения клиента. См. **Teste no jogo** ниже. Не добавляйте сохранения, личные логи, пароли, токены или проприетарные файлы игры.
